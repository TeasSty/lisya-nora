# Лисья нора — сайт-визитка с каталогом и заявками

Черновой сайт для магазина уникальных подарков «Лисья нора» (Выборг, Краснофлотская 4А).
Сделан как демо для владелицы магазина: витрина + каталог + форма заявки + простая
панель администратора, чтобы заявки не разбирались вручную по сообщениям ВК.

## Текущий этап: смотрим только дизайн

**Превью (бесплатно, работает прямо сейчас):** https://teassty.github.io/lisya-nora/

По договорённости сейчас в приоритете дизайн и вёрстка, а не подключённый backend.
Поэтому:

- Сайт задеплоен как **статика на GitHub Pages** — без сервера и базы данных.
- Каталог показывает те же демо-товары, но из статичного файла
  `src/data/demoProducts.ts`, а не из API.
- Форма заявки полностью работает как UI: валидация, состояние отправки, экран
  успеха — но сама заявка **не сохраняется** на сервере (это временно, см. ниже).
- Панель администратора (`/admin`) в этом превью не подключена и не показывается в
  навигации — вход по паролю и D1 backend уже написаны в коде (`worker/`,
  `src/pages/admin`), но их подключение — следующий шаг после согласования дизайна.

Переключатель этого поведения — один флаг `DEMO_MODE` в `src/lib/config.ts`. Когда
дизайн одобрят и backend будет развёрнут на Cloudflare, достаточно поставить
`DEMO_MODE = false` — весь остальной код (каталог, форма, админка) менять не нужно,
он уже написан так, чтобы одинаково работать в обоих режимах.

**Следующий шаг (после одобрения дизайна):** развернуть `worker/` на Cloudflare
Workers + D1 (инструкция ниже, раздел «Деплой backend»), переключить `DEMO_MODE` на
`false` — и заявки с сайта начнут реально попадать в панель администратора.

## Стек

- **Frontend**: React 19 + TypeScript, Vite, обычный CSS (без UI-фреймворков и
  motion-библиотек — вся анимация на CSS-переходах и `IntersectionObserver`).
- **Backend**: Cloudflare Worker (Hono) + Cloudflare D1 (SQLite) для каталога и заявок.
- **Деплой**: всё разворачивается ОДНИМ Cloudflare Worker'ом со статикой (Workers
  Assets) — фронтенд и API живут на одном домене, без отдельного хостинга.
- Сборка настроена через `@cloudflare/vite-plugin`, поэтому `vite dev` / `vite build`
  одновременно собирают и клиент, и Worker.

Почему так: GitHub Pages — чисто статический хостинг, там нет места для API и базы
данных, а форме заявок и панели администратора нужен настоящий backend с хранением
данных (иначе заявки будут «улетать в пустоту» или жить только в localStorage одного
браузера). Cloudflare Workers + D1 дают лёгкий backend бесплатно, без отдельного сервера.


## Как это работает (целевой режим, `DEMO_MODE = false`)

Ниже описано, как всё устроено при подключённом backend. Сейчас сайт опубликован в
демо-режиме (см. раздел выше) — визуально и по UX всё то же самое, просто заявки не
сохраняются на сервере, а каталог берётся из статичного файла.

### Публичный сайт

Сигнатурная фишка сайта — **«карта норы»**: категории товаров показаны как комнаты
лисьей норы (шкатулка с украшениями, часовой чулан, полка диковинок, уголок оберегов,
горница сувениров). Клик по комнате фильтрует каталог ниже. На мобильных — та же идея,
но в виде вертикальной тропы (не просто сжатая десктопная версия).

### Заявка на заказ

У каждого товара — кнопка «Оставить заявку». Открывается форма (имя, телефон,
комментарий), товар уже выбран автоматически. Заявка сохраняется в D1 через
`POST /api/orders` и сразу видна в панели администратора. Оплаты и доставки в этой
версии нет — по договорённости это осознанно вне scope черновика, но архитектура
(таблица `orders`, отдельный статус заявки) не мешает добавить это позже.

### Панель администратора (`/admin`)

- Вход по паролю (без логина/имени пользователя — максимально просто, как просили).
- **Заявки**: список всех заявок с сайта — имя, телефон (кликабельный, можно сразу
  позвонить), товар, комментарий, дата. Кнопка «Отметить выполненной» — чтобы видеть,
  что уже обработано.
- **Товары**: добавление / редактирование / удаление товаров каталога без участия
  разработчика — название, категория, описание, необязательная ссылка на фото,
  видимость на сайте, порядок отображения.

Сессия администратора — подписанный HMAC-токен в HttpOnly cookie (без библиотек и
без таблицы сессий в базе). Пароль сравнивается через постоянное время сравнения
(защита от timing-атак).

### Фото товаров

Реальных фото магазина найти не удалось (страница ВКонтакте недоступна для
автоматического парсинга без авторизации). Пока у товара нет фото — карточка
показывает не «заглушку», а осознанную часть дизайн-системы: тёплое пятно фирменного
цвета с рисованной иконкой категории (`src/components/site/ProductPattern.tsx`).
Как только у владелицы появятся фото — она сама вставляет ссылку на фото в поле
«Ссылка на фото» в панели администратора, и карточка товара сразу покажет
настоящую фотографию вместо узора.

## Локальный запуск

```bash
npm install

# Секреты для локальной разработки уже лежат в .dev.vars (не в git)
# Применить схему БД к локальной D1 (один раз, при первом запуске):
npm run db:migrate:local

npm run dev        # http://localhost:5173 — фронтенд + API + локальная D1
npm run build       # production-сборка (tsc + vite build)
npm run preview      # прогнать собранную сборку в Workers runtime локально
```

Локальный пароль администратора (только для разработки, см. `.dev.vars`): `lisa-dev-2026`.

## Деплой дизайн-превью (сделано, GitHub Pages)

Настроено автоматически: при каждом push в `main` GitHub Actions
(`.github/workflows/deploy-pages.yml`) собирает статичный фронтенд (`DEMO_MODE = true`,
без backend) и публикует его на GitHub Pages. Ничего дополнительно запускать не нужно.

- **Ссылка**: https://teassty.github.io/lisya-nora/
- Репозиторий сделан публичным — это требование бесплатного GitHub Pages для
  обычного аккаунта (иначе Pages для приватных репозиториев не работает на free-плане).
  В коде нет секретов и приватных данных, так что это безопасно.
- Прогресс сборки: вкладка **Actions** в репозитории на GitHub.

## Деплой backend (следующий этап, после согласования дизайна)

Полноценный backend (Cloudflare Worker + D1 для каталога и заявок, панель
администратора) уже написан и протестирован локально, но не развёрнут: в этой рабочей
среде нет авторизованного доступа к Cloudflare (`wrangler whoami` возвращает
«Not logged in», интерактивный логин недоступен). Когда дизайн одобрят, разверните
backend самостоятельно — это займёт 5–10 минут:

```bash
# 1. Войти в Cloudflare (откроется браузер)
npx wrangler login

# 2. Создать базу D1 и подставить её id в wrangler.jsonc (поле database_id)
npx wrangler d1 create lisya-nora-db

# 3. Применить схему и демо-данные к реальной (remote) базе
npm run db:migrate:remote

# 4. Задать секреты (пароль администратора и секрет для подписи сессий)
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SESSION_SECRET

# 5. Собрать и опубликовать
npm run deploy
```

После деплоя Cloudflare выдаст бесплатный адрес вида `https://lisya-nora.<ваш-поддомен>.workers.dev`
— это и есть рабочая ссылка на черновик, которую можно сразу показать владелице
магазина (desktop и mobile). Домен на reg.ru и переход на платный хостинг — отдельный
следующий шаг **после** её одобрения; когда домен будет готов, его достаточно
привязать к этому же Worker'у через Custom Domains в Cloudflare (DNS настраивается
один раз, без переписывания кода).

После получения реального адреса на Cloudflare (а позже — домена на reg.ru) обновите
`canonical` и `og:*`/`twitter:*` ссылки в `index.html` (сейчас там указан адрес
текущего GitHub Pages превью).

## Git

Репозиторий инициализирован, есть `.gitignore` (исключены `node_modules`, `dist`,
`.wrangler`, `.dev.vars` и любые `.env*` — секреты не попадают в git). Проверьте перед
пушем, что вы не коммитите свои личные `.dev.vars` с настоящими паролями.
